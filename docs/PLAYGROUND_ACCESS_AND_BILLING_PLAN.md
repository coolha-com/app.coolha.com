# ADR：Playground 访问策略、BYOK 连接与软件订阅定位

- 日期：2026-10-15
- 状态：已定案并落地（路径 A：只卖软件订阅，用户自带 Key）
- 背景：算力市场原先的形态是「聚合模型 + 统一网关 + 按 token 计费」。核实 Vercel 条款后确认该形态**合同上走不通**（转售第三方 AI provider 的 key、sell access 均被 AUP 禁止），因此产品定位调整为：**Coolha 只卖软件订阅，不卖模型算力、不转售任何 API 或 Key**。

## 决策零（总纲）：只卖软件订阅

- Coolha **不签发、不转售、不代理**任何 API Key；不赚 token 差价；不托管用户密钥。
- 付费能力以两种形式交付：
  1. **软件订阅**：解锁产品功能（多连接管理、路由策略、上下文管理、可观测性、导出等）；
  2. **自带 Key（BYOK）**：用户连接自己的模型服务，费用直接由用户的模型服务商结算。
- 免费模型体验由 Coolha 承担（上游本身免费，仅带宽与算力成本），作为产品获客入口。

## 决策一：公开访问仅允许免费模型（服务端硬门禁）

- `getPlaygroundModels()` 只返回**免费模型**（上游 `free` 标签，或输入/输出价格均为 0），前端自然看不到付费选项。
- `POST /api/compute/playground` 增加服务端断言：命中非免费模型直接返回 `403 PAID_MODEL_NOT_ALLOWED`。客户端过滤只是体验，**服务端才是闸门**。
- 实测：`callstack-apex`（付费）→ 403；`nvidia-nemotron-3-5-lightning-free`（免费）→ 真实流式调用正常。

## 决策二：API Keys 页改为「我的 API 连接」——用户自己的密钥管理

原 `/ai/api-keys` 的语义是「Coolha 签发 Key」（Phase 2 占位），与「不转售 Key」冲突，已整体改造：

- 页面语义变为**用户自己的模型服务连接管理**：名称、服务商预设（OpenAI / DeepSeek / OpenRouter / 硅基流动 / Moonshot / Groq / Ollama / 自定义）、Base URL、API Key、常用模型 ID。
- 存储：`src/lib/compute/connections.ts`（localStorage `coolha.connections`，`useSyncExternalStore` 模式，读取时字段校验）。旧版按模型存储的 `coolha.byok.models` 在首次读取时**自动归并迁移**为连接。
- 能力：添加 / 编辑 / 删除 / 启用停用 / **连通性测试**（浏览器直连 `{baseURL}/models`，不发送任何对话内容）。
- Playground 的「我的连接」分组直接复用这份连接（连接 × 常用模型 = 可选模型），单一事实来源。
- 页面底部固定声明：不签发、不转售任何 Key，连接信息与密钥只存浏览器，请求由浏览器直连，费用由用户账户承担。

## 决策三：Playground 改为标准 AI Chat 形态

- 单列全宽布局（移除右侧「本次调用」与「API 调用示例」两个说明面板及空态技术说明）。
- 模型下拉分两组：**免费模型（Coolha 提供）** / **我的连接（浏览器直连）**。
- **深度思考**开关：开启后在请求中注入分析指令（先拆解与评估，再逐步推理，最后给结论），并在免费模型不支持 reasoning 时明确提示「不返回推理过程」。
- **图片附件**：≤4MB，走 data URL；网关通道交由 AI SDK 的 file part 透传，BYOK 通道按 OpenAI 兼容 `image_url` 格式直发。附件不落库。
- 其他产品化细节：空态改为「今天想聊点什么」+ 建议问题 chips、输入框随内容自适应、Enter 发送 / Shift+Enter 换行、停止生成、重新生成、思考过程折叠、连接态与 token 用量提示收敛为底部一行。

## 决策四（规划）：网页搜索

「网页搜索」需要外部搜索供应商（Tavily / Brave / Serper / Bing 等），引入前需先定：

1. 由 Coolha 提供（需采购额度，等于我们承担第三方服务成本，且搜索结果会流入模型 = 数据处理责任）；
2. 用户自带搜索 Key（同 BYOK 模式，浏览器直连搜索 API，搜索结果由浏览器带入对话）；
3. 暂不做。

倾向方案 2（与「只卖软件、不卖算力」一致，且零成本），但需你确认后再实现。

## 决策三（规划）：订阅制的合规边界 ⚠️

**目标**：订阅后才可使用付费模型，按量计费。

**必须先解决的前置问题**：若订阅后仍由 Coolha 用 Vercel AI Gateway 的 Key 代用户调用付费模型并收费，**会直接违反 Vercel AUP**：

- 禁止 "sell access / make Services available to any third party"；
- 禁止 "Buy, sell or transfer Vercel's third-party AI providers' API keys"；
- 禁止用托管服务构建与上游竞争的同名产品；
- AI Product Terms §2：许可仅限 personal or internal business use，无 sublicense 权。

**因此订阅制只有三条合规路径**（与 2026-10-15 的合规调研结论一致）：

| 路径 | 形态 | 计费依据 |
|---|---|---|
| A. 卖产品能力（推荐） | 自有 AI 应用/Agent，模型调用封装在产品价值里 | 订阅费 |
| B. BYOK + 订阅软件 | 用户自己的 Key，订阅解锁软件功能（多模型路由、额度管理、可观测性） | 订阅费（不含 token 差价） |
| C. 自建算力 | 自购 GPU 部署开源模型，token 是自有库存 | 用量计费 |

**不允许**：把 Gateway 的 token 差价转售给站内用户（等于 key 转售 + access 转售，双重命中）。

**因此决策一、二与订阅制的关系**：付费模型能力以「用户自带 Key」或「自有部署模型」的形式提供；订阅卖的是软件能力与自有算力，而不是第三方 token 的转售价差。

## 成本归属一览

| 调用方 | 走哪条通道 | 谁付模型费 | Coolha 是否记录 |
|---|---|---|---|
| 访客 · 免费模型 | Coolha 服务端代理 Gateway | Coolha（模型本身免费，仅带宽/算力成本） | 是（`ai_gateway_usage`） |
| 订阅用户 · 自带 Key | 浏览器直连 | 用户自己的 Key | 否（刻意不记录） |
| 访客 · 付费模型 | — | — | 当前直接 403 拒绝 |

## 复核条件

- 若未来接入搜索能力，按决策四的方案选型执行。
- 若出现「浏览器直连被 CORS 拦截」成为主要投诉，再评估可选的服务端**无状态透传**（key 仅随请求过境、不落库、不记录），但需先做 SSRF 防护与端点策略，并重新审阅合规。
- 免费模型清单依赖上游目录；若上游把某模型改为收费，`isFreeModel` 会自动把它移出公开列表并立即被服务端门禁拦截，无需改配置。
- 订阅功能设计时须保持边界：售卖的是软件能力，不触碰第三方 token 的转售价差。
