# A 路线：用户付费使用路径与 Coolha 盈利模型

> 定稿日期：2026-10-16
> 路线：**留在 Vercel AI Gateway + 购买 Credits**（不自建网关、不自部署模型）
> 核心约束：**收入与第三方 token 成本彻底脱钩**——用户付的钱 100% 对应 Coolha 自己的软件与服务，
> 0% 对应第三方模型算力。这是整套方案不踩红线的根本原因。
>
> 相关文档：`docs/PRICING_AND_ENTITLEMENTS.md`（权益矩阵与链上收款）、
> `docs/ENTITLEMENT_ENFORCEMENT_STATUS.md`（权益落地审计与合规边界）

## 一、先看清一件事：钱和成本的流向

```
                     ┌─────────────────────────────────────────┐
   用户付的订阅费 $6/$10/$30 ──▶│  Coolha 的收入                        │
    （USDC/USDT 链上）           │  成本：服务器 + Neon + 存储            │
                                │  → 毛利 ≈ 95%                        │
                                └─────────────────────────────────────────┘

                     ┌─────────────────────────────────────────┐
   赞助模型的 token 费 ◀── Coolha 的 AI Gateway Credits（营销预算）
    ~$0.45/用户/月      与档位完全无关，所有登录用户拿一样的额度
                        → 这是获客成本，不是产品成本
                        └─────────────────────────────────────────┘

                     ┌─────────────────────────────────────────┐
   付费模型的推理费      ◀── 用户自己的 API Key（浏览器直连或用户自管）
                        Coolha 不经手、不计量、不分成
                        └─────────────────────────────────────────┘
```

**三条资金流完全隔离。** 订阅收入不流向供应商，赞助成本不随付费用户数增长。

## 二、用户付费使用路径（四态身份）

| 层级 | 条件 | 能做什么 | 不能做什么 |
|---|---|---|---|
| **L0 匿名** | 打开网页 | 浏览模型广场（目录+价格）、定价页、文档 | Chat 任何调用（401） |
| **L1 已连接钱包** | AppKit 连接（纯前端） | 同 L0，多显示一个地址 | 同上——**连接 ≠ 登录，无服务端凭据** |
| **L2 签名登录** | SIWE 签名换会话 Cookie | 见下方「L2 权益」 | 云端历史、检索、导出、API 出口 |
| **L3 订阅** | L2 + 链上付款到账 | 见下方「L3 权益」 | **不能**获得任何额外 token 额度或额外免费模型 |

### 2.1 L2 免费登录用户拿到什么

| 项 | 值 |
|---|---|
| 赞助模型对话 | **每日 300K tokens / 30 次**（全局常量，所有档位一样） |
| 可选模型 | 67 个「零数据保留 + 不用于训练 + 非 stealth」模型，输入价 ≤$1/M |
| 数据政策 | 供应商承诺不保留、不训练；我们另加 `disallowPromptTraining` 双保险 |
| 本机会话历史 | localStorage，最多 50 条 |
| BYOK 连接 | 2 个，浏览器直连，**不计量、不限流、不经过我们服务器** |
| 云端历史 | **无**（Free 档 `historyDays = 0`） |

### 2.2 L3 订阅用户额外拿到什么（全是软件）

| 能力 | Plus $6 | Pro $10 | Ultra $30 |
|---|---|---|---|
| 云端历史保留 | 90 天 | 365 天 | 永久 |
| 云端历史条数 | 500 | 5 000 | 无限 |
| 跨设备同步 | ✓ | ✓ | ✓ |
| 历史全文检索 | — | ✓ | ✓ |
| 导出 | 单条 MD | 批量 MD+JSON | 批量+定时+CSV |
| BYOK 连接数 | 5 | 15 | 无限 |
| Persona / 模板 | 10 / 5 | 无限 / 无限 | 无限 / 无限 |
| 多模型并排 | — | 2 路 | 4 路 |
| 路由策略 | — | ✓ | ✓ |
| 成本看板回看 | 90 天 | 365 天 | 永久 |
| API / Webhook / MCP 出口（用**用户自己的 Key**） | — | ✓ | ✓ |
| 支持 | 邮件 | 优先邮件 | 优先 + 1v1 |

### 2.3 关键路径：额度用完时发生什么

```
用户发起第 31 次请求
   │
   ▼
服务端 checkQuota() ─── 超限 ──▶ 429 QUOTA_EXCEEDED
   │                        「今日免费对话次数已用完（30/30 次）。
   │                         额度 UTC 明日 00:00 重置；
   │                         所有档位额度相同，升级不会增加——
   │                         你可以切换自己的模型继续。」
   ▼
用户有三个选择：
   1. 等明天 UTC 0 点重置           （免费）
   2. 接入自己的 API Key（BYOK）     （免费，无限量，费用用户自付上游）
   3. 订阅 Plus/Pro                  （解锁的是云端历史/同步/检索，不是更多额度）
```

**注意第 3 项的文案**：订阅入口存在，但明确告诉用户「升级不会增加免费额度」。
这不是慷慨，这是**合规必要**——一旦升级能买到更多 token，整条线就断了。

### 2.4 完整付费流程图

```
L0 匿名
  │  浏览模型广场 / 定价页
  ▼
L1 连接钱包（AppKit，纯前端）

  ▼
L2 签名登录（SIWE nonce → 签名 → httpOnly Cookie，7 天可撤销）
  │  获得每日 300K / 30 次统一额度
  │
  ├─▶ 额度够 ──▶ 正常对话，流式返回，落 usage_daily
  │
  ├─▶ 额度用完 ──▶ 429 + 引导 BYOK（不引导升级）
  │                    │
  │                    ▼
  │                 用户在 /ai/api-keys 填自己的 provider key
  │                 （localStorage，永不上行）
  │                    ▼
  │                 浏览器直连上游，Chat 正常用，我们不计量不限流
  │
  └─▶ 想要「换设备不丢历史 / 检索 / 导出」
         │
         ▼
       /ai/billing 选档位 → 选 Base + USDC
         │
         ▼
       服务端生成订单 { 金额带 0~9 分指纹, 收款地址, 30 分钟窗口 }
         │
         ▼
       用户从自己钱包转精确金额
         │
         ├─▶ 点「我已完成支付」→ 立即扫链（回溯 2.5 小时）→ 匹配 (from+amount+时间窗)
         ├─▶ 停留在账单页轮询 → 被动扫链（60s 节流）
         └─▶ Vercel Cron 每日一次兜底（Hobby 限制）
         │
         ▼
       匹配成功 → 入账 compute_ledger（幂等 tx_hash+log_index）
                → 写 entitlements { plan, status=active, period_end }
                → 二次校验 geo header（防绕地理屏蔽）
         │
         ▼
       L3 订阅生效：云端历史 / 同步 / 检索 / 导出解锁
```

## 三、Coolha 怎么赚钱

### 3.1 收入结构

| 来源 | 定价 | 性质 |
|---|---|---|
| **订阅（唯一主线）** | Plus $6 / Pro $10 / Ultra $30 每月，USDC/USDT 链上 | 软件即服务 |
| ~~token 差价~~ | — | **刻意不做**：Gateway zero markup 无批发价，且属转售 |
| ~~按量计费~~ | — | **刻意不做**：计量第三方 token 并收费 = 卖算力 |

### 3.2 成本结构

| 项 | 月成本 | 性质 |
|---|---|---|
| **赞助 token** | 日活免费用户 × ~$0.45（按满额 300K/天 估算） | 变动，但与**付费用户数无关** |
| Vercel | $0（Hobby）或 $20（Pro，若需高频 cron） | 固定 |
| Neon Postgres | $0（Free）或 $19（Launch） | 固定 |
| AI Gateway Credits | 按实际 token 消耗充值 | 变动 |
| 域名 / 杂项 | ~$2 | 固定 |

### 3.3 关键测算：为什么这个模式健康

**解耦额度后，每一个订阅都是接近纯利润，且不带来额外 token 成本。**

| 场景 | 月收入 | 月赞助 token 成本 | 毛利 |
|---|---|---|---|
| 10 个 Plus 订阅 + 100 日活免费用户 | $60 | ~$45（假设 10% 用户跑满） | ~$15 + 固定成本 |
| 50 个 Plus 订阅 + 500 日活免费用户 | $300 | ~$225 | ~$75 |
| 200 个 Plus 订阅 + 2000 日活免费用户 | $1 200 | ~$900 | ~$300 |

**对比红线模式**（按 token 分档）：付费用户越多、档位越高，我们烧得越多——**付费用户变成成本中心**，
规模越大亏越多。这就是为什么必须解耦。

> 上面的测算假设「10% 日活用户跑满 300K/天」。实际远低于此：300K tokens 约等于
> 150 轮中等长度对话，普通用户一周都碰不到一次上限。按 1% 跑满率重算，
> 1000 日活的赞助成本约 $4.5/月，几乎可以忽略。

### 3.4 盈亏平衡点

固定成本约 $20–40/月（Vercel Pro + Neon + 域名）。
赞助成本约 $0.045/月/日活用户（1% 跑满率）。

```
盈亏平衡 ≈ 固定成本 ÷ (订阅价 - 该订阅者带来的边际赞助成本)
         ≈ $30 ÷ ($6 - $0.045)
         ≈ 5 个 Plus 订阅
```

**5 个 Plus 订阅即打平。** 门槛极低。

### 3.5 为什么订阅有人买（价值锚点）

付费买的不是「更多 AI」，是**三件用时间堆出来的东西**：

1. **记忆**——云端历史 + 跨设备。换电脑、清缓存不丢。这是唯一真正「越用越离不开」的。
2. **检索**——几百条历史里全文搜索。历史越多越值钱，形成正反馈。
3. **出口**——导出、API、Webhook。把数据变成资产。

这三件事的共同点：**边际成本趋近于零，价值随使用时间线性增长，且完全长在我们自己的数据库里**。
竞争对手抄不走用户的历史，用户也搬不走。

## 四、必须死守的六条边界（代码 + 文案双层）

| # | 边界 | 实现位置 |
|---|---|---|
| 1 | **额度是全局常量，不是档位字段** | `plans.ts` 的 `SPONSORED_DAILY_TOKENS` / `SPONSORED_DAILY_REQUESTS`；已从 `PlanLimits` 删除 `quota` |
| 2 | **可赞助模型范围与档位无关** | `isSponsorableModel()` 判据；`getPlaygroundModels()` 不过滤档位 |

| 4 | **定价页/卖点禁写 token 类表述** | `SubscriptionPanel.HIGHLIGHTS` 文件头注释禁止；已删「额度提升至 X」 |
| 5 | **无付费优先排队、无并发差异** | 已从 `PlanLimits` 删除 `queuePriority` / `concurrentSessions` |
| 6 | **付费模型一律走用户自己的 Key** | 服务端 403 `MODEL_NOT_SPONSORED`；详情页引导 `/ai/api-keys` |

### 4.1 文案黑名单（写营销/定价页时逐条自查）

绝对不要出现：

- 「升级获得更多 tokens / 更高额度」
- 「解锁更多模型」（指赞助范围内的模型）
- 「更快响应 / 优先处理」
- 「用 Coolha 调用 GPT-5 / Claude」（暗示我们提供付费模型的访问权）
- 「无限对话」（除非明确指 BYOK）

可以出现：

- 「云端历史与跨设备同步」
- 「全文检索你的所有对话」
- 「导出为 Markdown / JSON」
- 「管理多个模型服务连接」
- 「免费模型由 Coolha 赞助，供应商承诺零数据保留、不用于训练」

### 6.1 本地优先实现要点

架构：**本地 IndexedDB 是唯一读源，云端只是可选镜像。**

```
  Chat UI ──写入──▶ IndexedDB（唯一读源，任何模式都写）
                      │
                      │ 仅当 mode === "backup" 且档位含云历史
                      ▼
                   云端镜像（跨设备恢复 / 换机备份）
```

- `src/lib/compute/local-db.ts` —— 零依赖 IndexedDB 封装，`threads` / `messages` / `meta` 三个 store。
  替代 localStorage（5–10MB 上限、同步阻塞、存不了图片）。
- `src/lib/compute/thread-store.ts` —— 统一存储。两种模式：
  - `local`（默认）：零服务端接触，未登录也能用本机历史；
  - `backup`：本地写完后后台镜像一份，**本地仍是读源**——云端宕机不影响对话。
- 旧版 `coolha.conversations`（localStorage）自动一次性迁移进 IndexedDB。
- 设置页（`/settings`）提供：模式切换、数据位置说明、立即备份 / 从云端恢复（合并不覆盖）、
  本机与云端**分别独立**清空。
- 删除的 `conversations.ts` 中 `newId` / `ByokHistoryMessage` 已迁入 `thread-store.ts`。

> 端到端验证（Playwright + 真实 IndexedDB）：旧 localStorage 数据迁移后 thread 2 条 / message 2 条 /
> 迁移标记 `true` / 新写入可读 / 设置页「本地优先」卡 `aria-pressed=true` / Chat 抽屉显示本地优先文案。

> ⚠️ 修掉一个真 bug：`replaceLocalMessages` 原先把 `put` 放在 `tx.oncomplete` 里，
> 此时事务已结束，抛 `TransactionInactiveError`。改为在 `openCursor` 遍历结束（仍在活动期）后统一插入。

## 七、一页总结

> **Coolha 卖的是一个 AI 对话工作台：模型切换、多连接管理、云端记忆、全文检索、数据出口。**
>
> 免费模型是我们赞助的试用装，**所有登录用户发一样多**，用完请自带 Key——这是获客成本，不是商品。
> 付费订阅买的是**我们自己的软件**：让你的对话历史可跨设备、可搜索、可导出、可编排。
>
> 用户付的钱进 Coolha，买我们的工程与存储；
> 用户调付费模型的钱进上游，用用户自己的 Key；
> 我们赞助免费模型的钱进 Vercel，是市场预算。
>
> **三条钱流永不交叉，所以永远不会踩线。**
