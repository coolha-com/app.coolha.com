## 1. 产品定位

### 1.1 我们在做什么

Coolha 不是一个新开的独立产品线，而是现有 `/ai` 算力市场的**演进**：从「多模型入口」升级为「Web3 通用 AI 工作台」。

核心命题：**让 AI 有能力碰链，但让权力留在用户手里。**

- AI 可以读链、分析、生成报告、起草交易；
- 但**密钥永不离开用户浏览器**，写操作先出草稿再由用户钱包签名；
- 给 Agent 的授权由**链上合约强制边界**（限额/白名单/时效），越权即回滚，且随时可撤。

### 1.2 市场空位（为什么是我们）

2026-10 竞品实测后的格局：

| 类型 | 代表 | 局限 |
| --- | --- | --- |
| 垂直交易终端 / 资金产品 | Capminal、Rigoblock、Arena | 绑定自有代币或自有金库；Arena 已变成 Robinhood Chain 上的 AI vault 募资产品 |
| 开发者基础设施 | MetaMask Agent Wallet（CLI）、Morpho/Pendle MCP | 非 DApp 形态或仅覆盖单一协议 |
| Agent 技术栈 | Bankr、Nani | 面向开发者/命令行，非通用工作台 |

**缺口**：没有一款同时做到「浏览器打开即用 + 连接你自己的钱包 + 多模型 + BYOK + 只读研究免费 + 写操作受治理 + Agent 授权可撤销」的通用工作台。最像的竞品是 **Capminal**，但它绑定 `$CAP` 代币经济、无 BYOK。

行业已收敛出三套标准，我们**站在标准上而非自建平行体系**：
- 工具分发 = **MCP + Agent Skills**
- Agent 授权 = **EIP-7702 + ERC-7715 + ERC-7710**（链上强制限额/白名单/时效）
- Agent 支付 = **x402**（HTTP 402 + USDC 按次结算，Linux Foundation 治理）

### 1.3 明确不做（四条边界）

1. **不做资金产品**——不发行金库、不托管用户资产、不做收益策略市场。
2. **不绑定代币**——产品能力不靠 token 解锁。
3. **不导入私钥/助记词**——只支持连接用户自己的钱包（这是安全卖点，也是与旧版 Nani 的界线）。
4. **不自建全部数据**——能用 Alchemy / Tenderly / DefiLlama 等标准件的不自建。

## 2. 目标

### 2.1 用户价值目标

| 目标用户 | 核心场景 | 用 Coolha 做什么 |
| --- | --- | --- |
| **Web3 研究者/投资者**（主） | 「帮我分析这个合约和它最近的资金流」 | 只读研究：合约解码、交易追踪、协议对比、报告生成（免费获客层） |
| **DApp / 合约开发者** | 「读这个合约，找风险点，给我测试用例」 | 开发辅助：静态扫描、测试生成、部署辅助 |
| **DeFi 操作者** | 「把 100 USDC 换 ETH，先给我看模拟结果」 | 受治理执行：草稿 → 模拟 → 签名 → 广播 → 回执解读 |
| **效率极客 / Agent 玩家** | 「每天用不超过 $20 在 Base 上定投 ETH，授权 30 天」 | Agent 自治：授权 → 周期执行 → 随时撤销 |

### 2.2 商业目标

**卖软件能力，不卖算力。**

- 订阅四档（USD/月）：**Free $0 / Plus $6 / Pro $10 / Ultra $30**
- 付费买的是 Coolha 自己的工程与存储：跨设备历史、全文检索、导出、连接管理、编排、API 出口
- 免费赞助模型是**获客试用装**，所有登录用户额度相同（日 300k tokens / 30 次），用完请自带 Key
- **盈亏平衡 ≈ 5 个 Plus**

**三条钱流永不交叉**（这是合规地基）：

| 钱流 | 去向 | 性质 |
| --- | --- | --- |
| 用户订阅费 | → Coolha | 收入 |
| 用户调用付费模型的费用 | → 上游（用用户自己的 Key） | 代付，不经我们 |
| 我们赞助免费模型的费用 | → Vercel | 市场预算 |

### 2.3 北极星指标（分阶段）

| 阶段 | 北极星指标 |
| --- | --- |
| Phase 1 只读研究 | 周活跃对话数；工具调用成功率 |
| Phase 2 受治理执行 | 草稿 → 签名转化率；风险拦截率 |
| Phase 3 Agent 授权 | 授权 7 日留存；Agent 执行成功率 |
| Phase 4 开放计费 | 外部 MCP 调用量；x402 收入 |

### 3.2 尚未真接入的部分 ⚠️

- **`/ai/tools` 31 个工具中，30 个仍标记 `integration: "none"`**：页面只做**选型展示**，不提供实际调用。P0 待接的是读数据/查链类（DefiLlama / Slither）与签名流（request-wallet-sign）。
- **`/ai/tools` 已接入 1 个（2026-11-03）**：`alchemy-mcp-server` → `integration: "live"`，执行点为服务端路由 `/api/ai/tools/[slug]`（Alchemy JSON-RPC 只读：区块高度 / 区块时间 / 原生币余额 / 交易计数，Base + Ethereum）。页面卡片内嵌「实测台」，点击即真实读链。Alchemy key 只在服务端读取；未配置时该路由返回 503 `not_configured`，**不返回任何链上数值**。返回值统一装在**证据信封** `ToolResult<T>` 里（数据源 / 方法 / 端点 / 链 / 抓取时间 / 延迟 / 覆盖范围 / 明确的「没查到」项），取不到的项如实标「未取到」，不填占位数值。⚠️ 接入的是 Alchemy 的链上数据能力，**不是官方 mcp.alchemy.com 的 MCP 端点**。
- **Alchemy 调用统一到 `src/lib/alchemy/client.ts`**：此前仓库里有三份各自为政的 Alchemy 代码（投前侦察硬编码 eth-mainnet、订阅扫链自己拼 URL、工具层又写一份）。现在只有一份实现，凭证读取、错误分类（未配置/超时/限流/鉴权/上游故障）与密钥脱敏都在这一处，投前侦察与工具层共用。
- **`/ai/research` 已接入真实数据源（2026-10-17 起）**：
  - 已接真数据：合约安全（Sourcify + Alchemy）、链上数据（Alchemy）、代币（DefiLlama）。报告数值均为真实抓取。
  - 未接入：项目方 / 团队（需链上实体图谱）、媒体情绪（需社交聚合源）——**这两类维度标记「数据源未接入」，不给任何数值与判断**。
  - 已**移除 0-100 风险分**：现有真实事实不足以支撑评分精度，编造分数等同于假数据，改为定性结论 + 依据说明（basis）。

## 4. 技术架构

四层 + 治理层（目标形态，当前工具层尚未填充）：

```
┌────────────────────────────────────────────────────────────┐
│ 交互层  对话 + 工具面板 + 交易草稿卡 + Agent 管理              │
├────────────────────────────────────────────────────────────┤
│ 治理层  写操作四道闸：模拟 → 威胁扫描 → 策略 → 签名            │
│         Agent 授权：ERC-7715 人话授权 → ERC-7710 caveat 链上强制│
├────────────────────────────────────────────────────────────┤
│ 工具层  MCP 风格注册表：只读 / 研究 / 开发 / 执行  ← 待接入    │
├────────────────────────────────────────────────────────────┤
│ 身份层  SIWE 会话 + EIP-7702 智能账户 + user_id 体系          │
├────────────────────────────────────────────────────────────┤
│ 模型层  BYOK（浏览器直连）+ AI Gateway catalog               │
└────────────────────────────────────────────────────────────┘
```

**关键工程约定**
- 本地 IndexedDB 是唯一读源，云端仅可选镜像（隐私叙事核心）
- 用户第三方 API Key **永不上行**
- 面向终端用户的查询**必须带 subject 过滤**；跨用户聚合数据不得出现在用户页面
- 构建铁律：`rm -rf .next && npm run build`（safe-delete 会拦截 next build 清目录）

## 6. 红线与合规

1. **密钥永不离开用户浏览器**；服务端不托管第三方密钥、不代售 Key。
2. **写操作先出交易草稿，再由用户钱包签名**；服务端永不代签。
3. **卖软件能力，不卖算力**——推理费由用户自己的 Key 承担，定价页明示。
4. **Vercel §8.3 合规**：真正红线是「按 token 数分档」，不是「有免费模型」。终端用户走 Gateway 须有独立 ToS + 隐私政策 + AI 披露。
5. **营销黑名单**：不得写「升级获得更多 tokens」「解锁更多模型」「更快响应」「用 Coolha 调用 GPT-5」。
6. **陈列即承诺**：定价页新增权益字段须同步标记「规划中」，已实现能力不得误挂 roadmap。
