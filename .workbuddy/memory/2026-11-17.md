### Creem 技术要点（核实自官方文档）
- 测试 API base `https://test-api.creem.io/v1`；key 前缀 `creem_test_`，header `x-api-key`。
- `POST /v1/checkouts` body：`product_id`、`request_id`（我们用它回传自己的单号）、`success_url`、`metadata`、`customer.email`；返回 `checkout_url`。
- webhook 签名：`creem-signature` 头 = HMAC-SHA256(raw body, secret) 的 **hex**，timingSafeEqual。未配 secret 返回 503。
- `checkout.completed` payload：`object.request_id`、`object.id`(ch_)、`object.order.{id,transaction,amount_paid}`、`object.customer.{id,email}`、`object.subscription.id`、`object.metadata`。授权事件另支持 subscription.active/paid；作废支持 refund.created/dispute.created。
- 幂等教训：事件表只 INSERT 审计、**不用它 gate 核销**（否则核销失败后重投被挡死）；重复发放由 source_order_id UNIQUE 拦截。

### AaaS 全链路验收（23:36 完成）
- 用户问「测试环境能否收钱+跑 AaaS+Neon/Creem/eve 调 OpenRouter」——实测回答：**能，但 closed 模式需授权**。
- OpenRouter 直连 HTTP 200（deepseek/deepseek-v4.1-flash-1017，真实 usage/cost）。
- dev:all 必须显式注入 `EVE_RUNTIME_ORIGIN=http://127.0.0.1:4274` + `EVE_INTERNAL_SECRET` + `COOLHA_EVE_LOCAL=1`，否则 /api/eve/v1/* 报 AGENT_RUNTIME_NOT_CONFIGURED（首轮 eve 进程没起稳也会报这个，看日志 `Listening on :4274` 确认）。
- 无授权跑 → PAYMENT_REQUIRED（402，闸门正确）；带临时授权跑 → **6/6 全过**：钱包登录/发授权/服务端会话绑授权/eve 派单(wrun_)/模型实回文本/usage_ledger 入账($0.0000996)。
- eve Client API 要点：baseUrl 传站点根（Client 内部自拼 /eve/v1），`sessions.create({message})` 返回 `{delivery, session}`，session.id 是 wrun_；文本在 `content.delta` 事件的 `data.delta`（过滤 `data.kind==='text'`），不是 data.parts。
- 坑：代理记账 session_id 写的是 `x-coolha-chat-session`（我们的 e2e_* 会话号），不是 eve 的 wrun_*，查账本别查错。
- 新增 `scripts/aaas-e2e.mjs`（AAAS_E2E_GRANT=1 开关发临时授权，自清理）；前几轮失败残留已手动清干净（授权2/会话1/账本4 → 全0）。
