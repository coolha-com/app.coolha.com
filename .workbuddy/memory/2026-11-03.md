- **新增前端实测台** `src/components/compute/ToolLiveRunner.tsx`（客户端组件）

### 关键设计取舍

1. **页面保持 `force-static`**。真实读链**不在渲染期发生** —— 实测台是客户端组件，点击后才请求我们自己的服务端路由。这样其余 30 个条目仍是零回源的纯静态条目，Alchemy key 也永远不到浏览器。
2. **接入的是 Alchemy 的链上数据能力，不是官方 `mcp.alchemy.com` 的 MCP 端点**。这两件事容易被混为一谈，所以写进了 `caveats` 和 `docs/ENTITLEMENT_ENFORCEMENT_STATUS.md` §14。官方 MCP 端点尚未接入。
3. **`readAlchemyKey()` 把空串当未配置**。若 `ALCHEMY_KEY=""` 而 `ALCHEMY_ID` 有效，空串不应该把有效值挡掉（`??` 只挡 null/undefined）。
4. **错误信息脱敏**：上游报错先 `split(key).join("[redacted]")` 再返回，避免 key 意外进响应体或日志。

### 做了什么

- **新增 `src/lib/alchemy/client.ts`**（`server-only`，**全站唯一**的 Alchemy 实现）
  - 凭证读取：`ALCHEMY_KEY` 优先 / `ALCHEMY_ID` 兜底 / **空串跳过**（`??` 挡不住空串）

  `hexToNumber` 原用 `Number.parseInt(hex, 16)`，**wei 超过 2^53 会静默丢精度**
  （1 ETH = 1e18 wei）→ 改 BigInt。
- **`subscription/scan.ts` 改用共享客户端**（删掉本地 `alchemyRpcUrl` 实现）
- **新增 `src/lib/web3-tools/evidence.ts`** —— 计划书 §4 的 `ToolResult<T>` + `trace()`

- **`web3-tools/alchemy.ts` 改为基于共享客户端**，返回 `ToolResult` 而非裸结构
- **`/api/ai/tools/[slug]` 路由**返回 `{status, result}`；错误分支带结构化 `error`
- **前端 `ToolLiveRunner.tsx`** 改渲染证据信封：新增展示 coverage（覆盖边界）、

### 踩坑（追加）

- TypeScript 的窄化在 JSX 里不跨行生效：`if (!result?.result?.data) return ...` 之后
  `const d = result.result.data` 仍报 `TS18047: 'd' is possibly 'null'`。
  → 先 `const d = envelope?.data ?? null` 再判空，`d` 才是可窄化的 `const`。
- `git status` 里 `deliverables/` 与 `docs/ARCHIVE_RWA_PROMPT_DRAFT_2026-10.txt` 是
  **本任务之前就存在的未跟踪文件**，不是本次改动 —— 提交时不要误带。
- `git stash` 会让 `core.autocrlf=true` 的仓库里部分文件（`AGENTS.md` / `SECURITY.md`）
  在 `git status` 里假报为「已修改」。**判定方法**：比 blob 哈希
  （`git hash-object <f>` vs `git rev-parse :<f>`）—— 相同即内容零变化，
  只是索引 stat 缓存脏了，`git checkout --` 刷新即可，不要误当成本人的改动。
- 构建的 `⚠ Compiled with warnings`（viem/ox 的 `Critical dependency`）**是既有的**：
  用 `git stash` 回退到基线重新构建，警告同样出现。来源是 `scan.ts` 里的
  `viem/chains` 导入链，与本次改动无关。
