> 承接 D-18 派单第 1 项。本条只记实现与验证，定位与合规口径以根 `MEMORY.md` 为准。

### 做了什么

- **新增服务端执行点** `src/app/api/ai/tools/[slug]/route.ts`
  - GET，`runtime = nodejs`，`dynamic = "force-dynamic"`
  - 只放行已接入的工具（当前集合只有 `alchemy-mcp-server`）；其余 slug → 404 `not_integrated`
  - 参数校验：`chain` ∈ {base, ethereum}；`address` 必须 0x + 40 位十六进制
  - 进程内滑动窗口限流 20 次/分钟/IP（与 playground 同一套思路）
  - **凭证缺失 → 503 `not_configured`；上游异常 → 502 `upstream_error`。任何分支都不返回占位数值**
- **新增数据客户端** `src/lib/web3-tools/alchemy.ts`（`import "server-only"`）
  - 复用既有约定：`ALCHEMY_KEY` 优先、`ALCHEMY_ID` 兜底（见 `docs/WEB3_TOOL_REGISTRY_PHASE1_PLAN.md` §1）
  - 链配置复用 `src/lib/subscription/config.ts` 的 `SUBSCRIPTION_CHAINS`（Base + Ethereum），不另建一份
  - 只读四个方法：`eth_blockNumber` / `eth_getBlockByNumber` / `eth_getBalance` / `eth_getTransactionCount`
  - 余额用 BigInt 转 wei 字符串，避免精度丢失；取不到的项返回 `null` 由上层标 unknown
- **新增前端实测台** `src/components/compute/ToolLiveRunner.tsx`（客户端组件）
  - 链切换 + 可选地址输入 → 打到 `/api/ai/tools/alchemy-mcp-server`
  - 失败分支如实显示「未配置 / 上游不可用 / 未接入」，不显示任何示例数值
- **目录状态翻转**：`catalog.ts` 的 `alchemy-mcp-server` → `integration: "live"`，`caveats` 写明接入范围
- **`/api/health` 扩展**：`services.alchemy.{configured, ok, detail}`。只报配置存在性 —— 健康检查不该消耗上游配额
- **页面文案按真实状态改写**：`/ai/tools` 顶部声明从「一个都还没接入」改成「1 个已接入，30 个尚未接入」

### 关键设计取舍

1. **页面保持 `force-static`**。真实读链**不在渲染期发生** —— 实测台是客户端组件，点击后才请求我们自己的服务端路由。这样其余 30 个条目仍是零回源的纯静态条目，Alchemy key 也永远不到浏览器。
2. **接入的是 Alchemy 的链上数据能力，不是官方 `mcp.alchemy.com` 的 MCP 端点**。这两件事容易被混为一谈，所以写进了 `caveats` 和 `docs/ENTITLEMENT_ENFORCEMENT_STATUS.md` §14。官方 MCP 端点尚未接入。
3. **`readAlchemyKey()` 把空串当未配置**。若 `ALCHEMY_KEY=""` 而 `ALCHEMY_ID` 有效，空串不应该把有效值挡掉（`??` 只挡 null/undefined）。
4. **错误信息脱敏**：上游报错先 `split(key).join("[redacted]")` 再返回，避免 key 意外进响应体或日志。
